DevOps промпт для аналізу вимог

Структура промпту для аналізу операційних потреб із дотриманням правил безпеки
Структура промпту
  • 1. Роль — операційний рев'юер вимог.
  • 2. Контекст — вимога, сервіси, топологія, середовища, ранбуки.
  • 3. Дія — виявити операційні потреби, прогалини та ризики.
  • 4. Вихід — таблиця доказів із власником і наступним кроком.
  • 5. Критерії якості — простежуваність, жодних вигаданих конфігурацій, явна невизначеність.
Правила безпеки
Секрети та значення
Ніколи не виводити секрети або прод-значення. Використовуйте плейсхолдери для чутливих параметрів.
Авторизоване джерело
Ідентифікуйте авторизоване джерело або власника для кожного параметра. Без цього — лише плейсхолдер.
Заборона інференсу
Xplore не вгадує прод-значення. Всі невідомі параметри позначаються як невизначені.
Обов'язкова інструкція: “Never output secrets or infer production values. Use placeholders for sensitive parameters and identify the authorized source or owner.”
