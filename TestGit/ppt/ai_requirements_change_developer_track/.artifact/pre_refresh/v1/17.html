Workflow DEV-3: Алгоритм аналізу технічного впливу

Процес аналізу впливу

9 кроків
  • 01Виявити змінені бізнес-правила — порівняти стару та оновлену базові лінії, визначити нові правила для критичного обслуговування.
  • 02Зіставити зміни з компонентами — визначити сервіси, що зачіпають правила (Ticket, SLA, Notification).
  • 03Перевірити споживачів API та подій — знайти клієнтів Ticket API, підписників подій, синхронізацію з CRM.
  • 04Проаналізувати дані та міграцію — оцінити нові поля, сховище ескалацій, вимоги до backfill.
  • 05Оцінити зворотну сумісність — чи можуть старі клієнти ігнорувати нове поле, версіонування схеми.
  • 06Розглянути фіча-флаги та fallback — захист нових шляхів, поведінка за замовчуванням.
  • 07Визначити взаємодію з технічним боргом — чи впливають накопичені обмеження на реалізацію.
  • 08Створити записи ризиків та залежностей — задокументувати прямі та транзитивні впливи.
  • 09Підготувати варіанти рішень — для схвалення технічним комітетом, з явними компромісами.
Фокус аналізу
  • Змінені бізнес-правила та їх технічне втілення
  • Мапування на компоненти ServiceHub
  • Перевірка міграції даних
  • Споживачі API та подій
