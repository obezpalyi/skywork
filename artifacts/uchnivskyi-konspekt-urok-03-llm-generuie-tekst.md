## Навіщо ми вивчаємо цю тему?

Чат-бот може написати пояснення, скласти план, перекласти текст, запропонувати ідеї або допомогти з кодом. Через це іноді здається, що він «думає» так само, як людина.

Щоб користуватися такими системами відповідально, потрібно розуміти:

- що означає LLM;
- як текст перетворюється на частини, придатні для обчислень;
- чому контекст змінює відповідь;
- як модель генерує текст крок за кроком;
- чому однаковий запит може давати різні результати;
- чому грамотно написана відповідь може містити неправду.

# Слайд 1. LLM: як машина генерує текст?

## Основна ідея

Велика мовна модель — це навчена математична система, яка працює із закономірностями людської мови.

Вона не має людського голосу «в голові» і не читає текст так, як ми. Для обчислень вона перетворює введений текст на спеціальні частини — токени — і працює з їхніми числовими представленнями.

### Спрощена картина

```text
запит користувача → токени → аналіз контексту
→ передбачення наступної частини → новий токен
→ повторення → готова відповідь
```

### Важливе уточнення

Слова «передбачає наступний токен» не означають, що модель просто випадково вгадує будь-яке слово. Вона використовує закономірності, набуті під час навчання на великій кількості текстів.

Водночас це не гарантує, що кожне створене твердження є правдивим.

# Слайд 2. Передбач наступне слово

## Інтерактивна вправа

Спробуй завершити речення:

> Взимку сніг зазвичай ______________________________.

Найімовірніші варіанти:

- падає;
- білий;
- тане;
- вкриває землю.

Різні учні можуть запропонувати різні продовження, але більшість варіантів будуть пов’язані з контекстом слова «взимку».

Тепер порівняй:

> Уранці після морозу сніг зазвичай ____________________.

> Навесні під сонцем сніг зазвичай ______________________.

Контекст змінює найдоречніше продовження.

## Що демонструє вправа?

Людина швидко оцінює, які слова можуть бути доречними далі. LLM робить щось подібне в математичній формі:

1. читає попередній контекст;
2. оцінює можливі продовження;
3. розподіляє між ними ймовірності;
4. обирає одне з них;
5. додає його до тексту;
6. повторює процес.

### Умовний приклад

Після фрази:

> «Кіт заліз на…»

модель може оцінити:

| Продовження | Умовна ймовірність |
|---|---:|
| дах | 45 % |
| дерево | 25 % |
| стіл | 15 % |
| підвіконня | 10 % |
| велосипед | 1 % |

Це лише ілюстрація. Реальні обчислення набагато складніші.

## Важливо

Ймовірність не означає гарантію. Найімовірніший варіант може бути:

- недоречним у конкретній ситуації;
- фактично неправильним;
- непридатним для мети користувача.

## Моє спостереження

У реченні «Кіт заліз на…» найдоречніше продовження для мене — __________________, тому що ____________________________________________________

# Слайд 3. Що означає LLM?

LLM — це абревіатура від англійського **Large Language Model**, українською — **велика мовна модель**.

Розглянемо кожне слово.

## Large — велика

Модель має багато внутрішніх параметрів і навчається на дуже великій кількості текстових прикладів.

«Велика» не означає, що модель фізично розуміє все на світі. Це опис масштабу системи та кількості закономірностей, які вона може враховувати.

## Language — мовна

Модель працює з мовними послідовностями:

- словами;
- частинами слів;
- реченнями;
- абзацами;
- знаками пунктуації;
- структурою тексту;
- зв’язками між частинами контексту.

## Model — модель

Модель — це математична структура, яка після навчання може оцінювати, які продовження тексту є ймовірними в певному контексті.

### Що LLM може робити?

- продовжувати текст;
- відповідати на запитання;
- перефразовувати;
- перекладати;
- узагальнювати;
- класифікувати текст;
- створювати приклади;
- генерувати код.

### Чого не випливає з назви LLM?

Назва не означає, що модель:

- має свідомість;
- має власні наміри;
- розуміє світ як людина;
- автоматично перевіряє факти;
- пам’ятає кожну відповідь як людина;
- завжди знає, коли помиляється.

# Слайд 4. Текст перетворюється на токени

## Що таке токен?

**Токен** — це частина тексту, з якою працює мовна модель.

Токеном може бути:

- ціле слово;
- частина слова;
- розділовий знак;
- число;
- пробіл або його частина;
- спеціальний символ.

Точний поділ залежить від токенізатора та мови.

## Приклад

Слово **«інформатика»** може бути поділене на частини:

```text
«інформатика» → «інформа» + «тика»
```

А речення може містити:

```text
«Сьогодні» + « » + «ми» + « » + «вивчаємо» + « » + «LLM» + «.»
```

Це навчальна ілюстрація. Реальний токенізатор може поділити текст інакше.

## Навіщо потрібні токени?

Комп’ютерні моделі не опрацьовують людські слова безпосередньо як людина. Токени переводять текст у форму, яку можна:

1. перетворити на числові ідентифікатори;
2. подати моделі;
3. порівнювати з іншими токенами;
4. враховувати в контексті;
5. використовувати для передбачення наступної частини.

### Послідовність

```text
текст → токени → числа та вектори → обчислення → нові токени → текст
```

## Важливі наслідки

### Різні мови можуть токенізуватися по-різному

Одне й те саме поняття в українській, англійській та іншій мові може містити різну кількість токенів.

### Довший текст потребує більше обчислень

Чим більше токенів у запиті та відповіді, тим більше контексту потрібно обробити.

### Токен не завжди дорівнює слову

Одне слово може складатися з кількох токенів, а один токен іноді може містити частину слова або знак.

## Перевір себе

1. Чи є токен завжди цілим словом? _________________________________
2. Для чого текст перетворюють на токени? __________________________
3. Які символи, крім слів, можуть бути токенами? ____________________

## Спробуй самостійно

Поділи на можливі частини слова:

- «перетворення» → ________________________________________________
- «модель» → _____________________________________________________
- «інформатика» → ________________________________________________

Пам’ятай: у різних системах поділ може бути різним.

# Слайд 5. Контекст змінює продовження

## Що таке контекст?

**Контекст** — це текст або інформація навколо фрагмента, яка допомагає визначити його значення та доречне продовження.

Розглянемо фразу:

> «Він узяв ключ…»

Без додаткової інформації незрозуміло, про який ключ ідеться.

### Побутовий контекст

> Він узяв ключ від квартири й відчинив двері.

### Автомобільний контекст

> Він вставив ключ у замок запалювання автомобіля.

### Криптографічний контекст

> Він згенерував ключ для шифрування повідомлення.

### Контекст задачі

> У рівнянні потрібно знайти ключову змінну для подальшого розв’язання.

Слово «ключ» однакове, але продовження та значення залежать від контексту.

## Як контекст використовує LLM?

Модель враховує:

- попередні слова;
- тему розмови;
- стиль;
- мову;
- роль, яку їй поставили;
- обмеження запиту;
- попередні повідомлення діалогу.

## Вікно контексту

Модель може враховувати лише певний обсяг тексту за один раз. Цей обсяг називають **вікном контексту**.

Якщо діалог стає надто довгим, частина ранньої інформації може:

- перестати враховуватися;
- бути стиснута;
- впливати слабше;
- випасти з доступного контексту.

## Практична порада

Якщо відповідь стала неточною, спробуй:

1. коротко нагадати мету;
2. повторити важливі вихідні дані;
3. прибрати зайву інформацію;
4. чітко вказати формат результату.

## Моє пояснення

Контекст важливий, тому що __________________________________________

______________________________________________________________________

# Слайд 6. Як народжується відповідь

Генерація відповіді відбувається послідовно.

## Крок 1. Користувач вводить промпт

Наприклад:

> Поясни одинадцятикласнику, що таке алгоритм, у трьох абзацах і з одним прикладом.

## Крок 2. Промпт перетворюється на токени

Модель отримує не лише звичайний текст, а його токенізоване представлення.

## Крок 3. Модель аналізує контекст

Вона враховує:

- тему;
- мову;
- довжину;
- бажаний стиль;
- попередній текст;
- інструкції користувача.

## Крок 4. Модель передбачає наступний токен

Вона оцінює багато можливих продовжень і вибирає одне.

## Крок 5. Новий токен додається до контексту

Щойно модель створила один токен, він стає частиною тексту, який враховується далі.

## Крок 6. Процес повторюється

Модель знову прогнозує наступний токен, поки:

- не завершить відповідь;
- не досягне заданої довжини;
- не отримає спеціального сигналу завершення.

### Схема

```text
промпт
  ↓
токен 1
  ↓
токен 1 + контекст → токен 2
  ↓
токени 1–2 + контекст → токен 3
  ↓
...
  ↓
готова відповідь
```

## Важливо запам’ятати

> Відповідь не обов’язково з’являється в моделі як готовий цілісний текст. Вона будується крок за кроком.

Це допомагає зрозуміти, чому на початку відповіді модель може вибрати невдалий напрям, а потім продовжити його послідовно.

## Перевір себе

Розстав етапи в правильному порядку:

- модель обирає наступний токен;
- користувач вводить запит;
- відповідь завершується;
- токен додається до контексту;
- текст перетворюється на токени.

# Слайд 7. Гра «Жива мовна модель»

## Мета гри

Імітувати покрокову роботу мовної моделі та побачити, як новий текст змінює подальший контекст.

## Початок

```text
Сьогодні на уроці ми...
```

## Правила

1. Кожна група пропонує кілька можливих наступних слів або фраз.
2. Група оцінює їхню умовну ймовірність.
3. Обирається один варіант.
4. Обраний варіант додається до речення.
5. Група знову пропонує продовження, але вже з оновленим контекстом.
6. Порівнюються різні траєкторії генерації.

# Слайд 8. Чому відповіді можуть відрізнятися?

Один і той самий запит не завжди дає однаковий результат.

## Причина 1. Багато можливих продовжень

У мові часто є кілька правильних або доречних варіантів. Модель може обрати один із них.

## Причина 2. Налаштування випадковості

У генерації можуть використовуватися параметри, які впливають на різноманітність відповіді.

Умовно:

- нижча випадковість — відповіді стабільніші та передбачуваніші;
- вища випадковість — відповіді різноманітніші, але можуть бути менш точними або менш послідовними.

Точні назви та діапазони параметрів залежать від конкретного сервісу.

## Причина 3. Чутливість до формулювання

Невелика зміна промпту може змінити:

- рівень складності;
- тон;
- структуру;
- вибір прикладів;
- довжину;
- висновок.

Порівняй:

> «Поясни алгоритми».

і

> «Поясни учневі 11 класу поняття алгоритму простими словами, у 5 реченнях, із прикладом навігатора».

Другий запит задає більше орієнтирів.

## Як оцінити відповідь?

### Корисність

Чи допомагає відповідь виконати поставлену задачу?

### Точність

Чи відповідає вона фактам і наданому контексту?

### Відповідність

Чи дотримано обмежень: мови, обсягу, формату, рівня складності?

# Слайд 9. Чому LLM може впевнено помилятися?

## Головна різниця

Мовна модель переважно оптимізована на створення **правдоподібного продовження**, а не на автоматичне доведення істинності кожного речення.

Тому:

> **Впевнений тон не дорівнює достовірності.**

## Як виникає помилка?

Модель може:

- продовжити речення за схожим мовним шаблоном;
- змішати кілька різних фактів;
- неправильно зрозуміти запит;
- вигадати неіснуючу назву, дату або джерело;
- використати застарілу чи неповну інформацію;
- не розпізнати, що даних недостатньо.

## Чому текст звучить переконливо?

Модель добре відтворює:

- граматику;
- структуру пояснення;
- академічний або дружній стиль;
- зв’язки між словами;
- типові формулювання.

Але граматична правильність і стилістична впевненість не доводять фактологічної правильності.

## Що робити користувачу?

1. Виділити твердження, які можна перевірити.
2. Перевірити важливі факти за надійними джерелами.
3. Не покладатися на вигадані посилання.
4. Попросити модель назвати припущення та невизначеність.
5. Порівняти відповідь із підручником, офіційним сайтом або первинним джерелом.

# Слайд 10. Підсумок і домашнє завдання

## Три головні тези

1. **LLM працює з токенами** — частинами тексту, числами та знаками, а не з людськими поняттями безпосередньо.
2. **Модель використовує контекст**, щоб оцінити найімовірніше продовження.
3. **Відповідь генерується послідовно**, крок за кроком, а не обов’язково з’являється одразу як готовий текст.

## Домашнє завдання

Напиши коротке пояснення для молодшого школяра:

> Чому чат-бот іноді відповідає впевнено, але помиляється?

Обсяг — **5–7 речень**. Обов’язково використай щонайменше два поняття:

- токен;
- контекст;
- передбачення наступного токена;
- правдоподібність;
- перевірка фактів.

### План відповіді

1. Поясни, що LLM працює з текстовими частинами — токенами.
2. Скажи, що модель використовує контекст.

4. Наведи приклад можливої помилки.
5. Заверши правилом: важливі твердження потрібно перевіряти.

## Словник уроку

| Термін | Пояснення |
|---|---|
| LLM | Велика мовна модель, яка працює із закономірностями тексту |
| Велика мовна модель | Навчена математична система для аналізу й генерації текстових послідовностей |
| Токен | Частина тексту: слово, частина слова, знак або інший фрагмент |
| Токенізація | Перетворення тексту на послідовність токенів |
| Контекст | Інформація навколо фрагмента, яка впливає на його значення та продовження |
| Вікно контексту | Обсяг тексту, який модель може враховувати за один раз |
| Імовірність | Числова оцінка можливості певного продовження |
| Генерація | Створення відповіді послідовним додаванням нових токенів |
| Промпт | Запит або інструкція користувача для моделі |
| Правдоподібність | Наскільки текст звучить природно та переконливо |
| Достовірність | Відповідність твердження реальним перевіреним фактам |
| Галюцинація | Переконлива, але вигадана або фактично неправильна відповідь моделі |

## Підсумкова формула

> LLM не «виймає готову думку» з пам’яті. Вона аналізує контекст і крок за кроком добирає ймовірне продовження. Тому зв’язність відповіді потрібно відрізняти від її достовірності.
