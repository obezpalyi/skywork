# Слайд 1. Prompt engineering

## Що означає назва?

**Prompt engineering** можна перекласти як **проєктування або інженерія промптів**.

Це не магічний набір секретних фраз. Це вміння:

1. чітко описувати задачу;
2. надавати моделі потрібний контекст;
3. задавати очікуваний формат;
4. встановлювати обмеження;
5. перевіряти результат;
6. уточнювати інструкцію, якщо відповідь не підходить.

## Основна ідея

Промпт — це інструкція для моделі. Чим точніше описано мету та умови, тим менше неоднозначності залишається у відповіді.

Проте навіть хороший промпт не гарантує ідеального результату. Відповідь потрібно прочитати, перевірити та за потреби доопрацювати.

## Питання для роздумів

3. Хто відповідає за фінальний результат — модель чи користувач?

# Слайд 3. Що таке промпт?

## Визначення

**Промпт** — це текстовий запит, інструкція або набір умов, які користувач передає моделі, щоб отримати певний результат.

Промпт може містити:

- питання;
- наказ або прохання;
- вихідні дані;
- приклад бажаного результату;
- обмеження;
- формат відповіді;
- критерії перевірки.

## Приклади промптів

### Запитання

> Що таке машинне навчання?

### Інструкція

> Склади план підготовки до контрольної роботи з інформатики.

### Запит із контекстом

> Я вже знаю змінні та умови в Python. Поясни мені цикл `for` на прикладі обробки списку оцінок.

### Запит із форматом

> Подай відповідь у таблиці з колонками «Поняття», «Пояснення», «Приклад».

## Prompt engineering включає три навички

### 1. Формулювання задачі

Потрібно зрозуміти, який саме результат нам потрібен.

### 2. Підготовка контексту

Модель повинна знати важливі умови, вихідні дані та рівень користувача.

### 3. Критичне оцінювання

Потрібно визначити, чи відповідає результат меті, фактам і вимогам.

## Важливо

> Промпт — це не «правильне заклинання», яке змушує модель завжди казати правду. Це спосіб чітко пояснити завдання та умови роботи.

# Слайд 4. Формула якісного промпту

Універсальної формули для всіх задач немає, але часто корисно перевірити шість компонентів.

## 1. Роль або спосіб допомоги

Ким або яким помічником має бути модель?

Приклади:

- учитель, який пояснює тему;
- редактор тексту;
- наставник із програмування;
- консультант із планування;
- критичний перевіряльник аргументів.

Роль задає стиль і тип допомоги, але не перетворює модель на справжнього фахівця з гарантованими знаннями.

## 2. Аудиторія

Для кого створюється результат?

- для учня 5 класу;
- для одинадцятикласника;
- для батьків;
- для технічної команди;
- для людини без спеціальної підготовки.

## 3. Завдання

Що саме потрібно зробити?

Невдало:

> Розкажи про програмування.

Краще:

> Поясни різницю між змінною та константою на двох простих прикладах.

## 4. Контекст

Які вихідні дані важливі?

- що вже відомо;
- яка мета;
- у яких умовах виконуватиметься завдання;
- що вже було зроблено;
- які приклади потрібно врахувати.

## 5. Обмеження

Які межі потрібно встановити?

- мова;
- обсяг;
- рівень складності;
- кількість пунктів;
- заборонені елементи;
- часові рамки;
- вимоги безпеки.

## 6. Формат і критерії

Як має виглядати відповідь і як зрозуміти, що вона добра?

Формати:

- список;
- таблиця;
- план;
- покрокова інструкція;
- код із коментарями;
- тест із відповідями;
- короткий абзац.

Критерії:

- без фактичних помилок;
- зрозуміло для заданої аудиторії;
- містить приклади;
- відповідає обсягу;
- позначає невизначеність;
- не містить приватних даних.

## Схема

```text
роль + аудиторія + завдання + контекст
+ обмеження + формат + критерії перевірки
```

## Важливо

Не кожен промпт повинен містити всі компоненти. Обирай ті, які справді потрібні для задачі.

# Слайд 6. Обмеження, формат і перевірка

## Обмеження

Обмеження роблять результат керованішим.

Можна вказати:

- «українською мовою»;
- «до 150 слів»;
- «5 пунктів»;
- «без професійного жаргону»;
- «для учня 11 класу»;
- «додай по одному прикладу»;
- «не вигадуй джерела»;
- «якщо даних недостатньо — постав уточнювальні запитання».

## Формат відповіді

Формат допомагає швидко використати результат.

### Список

> Подай 5 правил безпечної роботи в інтернеті маркованим списком.

### Таблиця

> Порівняй алгоритм і модель у таблиці з трьома колонками.

### План

> Створи план виступу з вступом, трьома аргументами та висновком.

### Код

> Напиши код Python із коментарями до кожного важливого кроку.

### Тест

> Склади 5 тестових запитань із чотирма варіантами відповіді та познач правильну.

## Перевірка результату

Можна попросити модель допомогти з перевіркою:

- назвати припущення;
- виділити твердження, які потребують перевірки;
- показати можливі слабкі місця;
- навести контрприклад;
- порівняти два варіанти;
- поставити до трьох уточнювальних запитань;
- вказати, що вона не може підтвердити.

### Приклад

> Після відповіді окремо назви 3 твердження, які потрібно перевірити за надійними джерелами.

- домашню адресу;

# Слайд 8. Ітерація: перша відповідь не фінальна

## Що таке ітерація?

**Ітерація** — це повторення циклу «створити → оцінити → покращити».

Перший промпт рідко є ідеальним. Це нормально: ми використовуємо відповідь як матеріал для наступного уточнення.

## Цикл роботи

```text
1. створити промпт
2. отримати відповідь
3. оцінити результат
4. знайти проблему
5. уточнити інструкцію
6. перевірити нову відповідь
↺ повторити за потреби
```

## Приклади уточнень

### Якщо відповідь надто загальна

> Додай конкретні приклади з життя одинадцятикласника.

### Якщо пояснення складне

> Перепиши для учня без попередньої підготовки, поясни терміни простими словами.

### Якщо формат незручний

> Подай інформацію в таблиці з колонками «Крок», «Дія», «Приклад».

### Якщо не видно припущень

> Окремо назви, які припущення ти зробив, і що потрібно уточнити.

### Якщо бракує критичного погляду

> Наведи один контрприклад і назви обмеження запропонованого підходу.

### Якщо даних недостатньо

> Спочатку постав до трьох уточнювальних запитань, а потім запропонуй відповідь.

# Слайд 9. Шаблон безпечного промпту

Скористайся цим шаблоном як відправною точкою.

```text
Ти — [роль або спосіб допомоги].

Допоможи [аудиторії] виконати [конкретне завдання].

Контекст:
[що вже відомо, яка мета, які вихідні дані важливі].

Обмеження:
[мова, обсяг, рівень складності, кількість пунктів,
заборонені елементи, часові рамки].

Формат відповіді:
[список / таблиця / план / код / приклади].

Критерії якості:
[що має бути зрозумілим, точним, перевірюваним].

Якщо даних недостатньо, спочатку постав до 3 уточнювальних запитань.
Наприкінці вкажи, що потрібно перевірити самостійно.
```

## Правила безпеки

### 1. Без приватних даних

Не передавай паролі, адреси, документи, приватні фото та інші чутливі відомості.

### 2. Уточнювальні запитання

Якщо контексту не вистачає, попроси модель спочатку поставити до трьох запитань.

### 3. Перевірка фактів

Попроси окремо вказати твердження, які треба перевірити.

### 4. Автор — користувач

ШІ може допомагати з ідеями, структурою та чернеткою, але ти відповідаєш за фінальний текст.

### 5. Остаточне рішення — за людиною

Не приймай важливих рішень автоматично лише на підставі відповіді моделі.

# Слайд 10. Підсумок і exit ticket

## Критерії якісного промпту

Хороший промпт:

- чітко описує бажаний результат;
- містить достатній контекст;
- визначає аудиторію та рівень складності;
- встановлює формат і межі;
- не містить приватних даних;
- передбачає перевірку результату;
- може бути вдосконалений після першої відповіді.

## Exit ticket

Склади промпт для створення плану підготовки до контрольної роботи з інформатики.

Обов’язково додай:

- роль моделі;
- аудиторію;
- конкретне завдання;
- контекст;
- обмеження;
- формат;
- прохання вказати, що потрібно перевірити.

- [ ] критерії якості;
- [ ] прохання про уточнення;
- [ ] прохання назвати, що потрібно перевірити;
- [ ] немає приватних даних.

## Домашнє завдання

Створи **три версії промпту** для однієї корисної задачі:

1. початкову — коротку й просту;
2. уточнену — із контекстом, обмеженнями та форматом;
3. фінальну — після уявної оцінки відповіді.

Для кожної версії запиши:

- сам промпт;
- який результат ти очікуєш;
- що саме покращено;
- яку частину відповіді потрібно перевірити.

## Словник уроку

| Термін | Пояснення |
|---|---|
| Промпт | Запит або інструкція для моделі |
| Prompt engineering | Проєктування, уточнення та оцінювання промптів |
| Роль | Вказівка, яким способом модель має допомагати |
| Аудиторія | Люди, для яких створюється відповідь |
| Контекст | Вихідна інформація, мета та умови задачі |
| Обмеження | Межі щодо мови, обсягу, стилю, кількості або заборон |
| Формат | Бажана форма відповіді: список, таблиця, план, код тощо |
| Критерії якості | Ознаки, за якими перевіряють результат |
| Ітерація | Повторний цикл покращення промпту та відповіді |
| Уточнювальне запитання | Запит, який допомагає отримати відсутній контекст |
| Контрприклад | Приклад, що показує обмеження або слабке місце твердження |
| Приватні дані | Відомості, які можуть ідентифікувати або зашкодити людині |

## Підсумкова формула

> Якісний промпт пояснює, кому, що, навіщо, у якому вигляді та за яких обмежень потрібно підготувати. Але остаточна відповідальність за перевірку й використання результату залишається за людиною.
